# Portfolio enquiry API

This service backs the React + Vite contact form. It stores enquiries in DynamoDB and sends notifications to the configured Gmail inbox through Amazon SES.

## Architecture

Browser form → API Gateway REST API → Lambda (Python 3.12) → DynamoDB  
　　　　　　　　　　　　　　　　　　　　　　　　　└→ Amazon SES → Gmail inbox

The API stores the enquiry before attempting email delivery. If SES delivery fails, the record remains stored with `notificationStatus=PENDING`; inspect Lambda logs and the DynamoDB record. A retry/re-drive workflow is a future hardening task.

## Deploy

Prerequisites: AWS CLI, AWS SAM CLI, an AWS account, and an SES sender identity verified in the deployment region.

1. Verify the sender email identity in Amazon SES in the AWS region you will deploy to.
2. If the SES account is still in sandbox, request production access or verify the destination email address too.
3. Deploy the stack:

```bash
cd backend
sam build
sam deploy --guided
```

Provide these parameters:
- `AllowedOrigin`: exact production origin, for example `https://jenidevops.in`.
- `NotificationEmail`: the Gmail inbox where notifications should arrive.
- `SesFromEmail`: the verified SES sender identity.
- `RetentionDays`: default 180 days; choose a retention period appropriate for enquiry records.

4. Copy the `ContactApiUrl` stack output.
5. Set `VITE_CONTACT_API_URL` to that URL in the frontend build environment (GitHub Actions repository variable is suitable; it is a public endpoint, not a secret).
6. Rebuild and deploy the frontend after the API is deployed.

## API contract

`POST /enquiries` with JSON:

```json
{
  "name": "Visitor name",
  "email": "visitor@example.com",
  "subject": "Infrastructure consultation",
  "message": "At least twenty characters describing the enquiry.",
  "website": ""
}
```

Successful response: HTTP 202 with a confirmation message and reference ID.

Validation is repeated in Lambda; browser validation is not trusted. The API also applies API Gateway stage throttling (2 requests/second, burst 5), a body-size limit, and a honeypot check. CORS is restricted to the configured origin. DynamoDB encryption at rest, point-in-time recovery, and TTL retention are enabled.

## Operational and security notes

- Never place AWS credentials, SES credentials, or other secrets in Vite variables or frontend source.
- Use a dedicated Lambda execution role generated by SAM. SES currently uses a scoped action list; before production, replace `Resource: "*"` with the verified SES identity ARN for the chosen region/account.
- Add AWS WAF/risk-based controls and stronger per-IP/per-email abuse protection before promoting this public endpoint.
- Add CloudWatch alarms for Lambda errors/throttles and SES send failures.
- Restrict DynamoDB console access to authorized operators. Enquiry records contain personal data; do not log message bodies or email addresses.
- SES delivery is email notification to a Gmail inbox; this does not use the Gmail API or create Gmail labels.
- No AWS resources are created by committing these files. Deployment is a separate, explicit operation.
