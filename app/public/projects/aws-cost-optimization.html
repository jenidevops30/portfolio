Enforce Guardrails
1. Discovery & Allocation Tagging

Enforced required AWS Cost Allocation Tags (Environment, Application, Owner) to eliminate unallocated spend and establish accountability across workloads.

2. Telemetry & Metrics Profiling

Used AWS Cost Explorer, Compute Optimizer, and CloudWatch metrics over 30 days to measure p95 and peak CPU, memory, network, and disk I/O demands before proposing any changes.

3. Low-Risk Waste Elimination

Safely eliminated zombie resources that incurred costs with zero functional benefit: detached EBS volumes, unassigned Elastic IPs, and stale EBS snapshots.

4. Measured Architecture Rightsizing

Downsized compute nodes based on validated p95 resource profiles while keeping burstable headroom for traffic spikes, ensuring zero performance SLA degradation.

5. Storage Modernization (gp2 → gp3)

Converted all eligible EBS volumes from older generation gp2 to modern gp3 in-place with zero downtime, gaining higher baseline performance at 20% lower cost.

6. Proactive Budget Guardrails

Configured AWS Budgets alerts ($350 target with 85% threshold notifications) and Cost Anomaly Detection to catch spend spikes before the monthly billing cycle closes.

TECHNICAL EXECUTION HOW IT WAS IMPLEMENTED
STORAGE OPTIMIZATION

gp2 to gp3 Live Volume Migration

Migrated 14 EBS volumes using the AWS CLI without detaching or stopping active EC2 instances: aws ec2 modify-volume --volume-id vol-xxxx --volume-type gp3. Transitioned seamlessly from gp2's $0.10/GB-month to gp3's $0.08/GB-month with baseline 3,000 IOPS and 125 MB/s throughput included.

COMPUTE RIGHTSIZING

Telemetry-Backed Instance Rightsizing

Compute Optimizer flagged instances where average CPU hovered under 8% with peak RAM utilization under 45%. Replaced expensive c5.2xlarge (8 vCPU, 16 GB RAM at ~$0.34/hr) with t3.large (2 vCPU, 8 GB RAM at ~$0.0832/hr), reducing hourly compute cost by 75% per node.

AUTOMATED SCHEDULING

Dev & Staging Off-Hours Shutdown

Engineered an automated serverless lifecycle scheduler using Amazon EventBridge cron rules and an AWS Lambda function (Python). Non-production environments stop automatically at 19:00 UTC and boot at 07:00 UTC on weekdays, eliminating 65% of weekly dev compute spend.

DATABASE ARCHITECTURE

RDS Staging Multi-AZ Elimination

Evaluated staging requirements: Multi-AZ failover was costing double for a non-production test environment. Converted staging to Single-AZ while maintaining automated 7-day snapshots and point-in-time recovery, immediately halving the staging RDS bill.
